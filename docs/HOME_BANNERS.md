# 首页轮播

后台入口：`/admin/home-banners`。首页在原有内容前展示当前生效的轮播图；首次部署为空，管理员发布后显示，不自动插入营销内容。

## 数据与接口

- `GET /api/v1/home-banners`：公开读取，仅返回已上架且在展示时间内的数据，按 `sortOrder` 升序、创建时间降序排列。结束时间为排他边界。
- `GET /api/v1/admin/home-banners`：管理员读取全部记录。
- `POST /api/v1/admin/home-banners`：创建。
- `PUT /api/v1/admin/home-banners/{id}`：完整更新。
- `DELETE /api/v1/admin/home-banners/{id}`：删除，记录不存在时返回 404。
- 图片上传使用独立的 `POST /api/v1/admin/home-banners/images`（PNG/JPG/WebP），返回公开的站内文件地址；不会创建公告或通知。
- 轮播图原文件直接保存，保留像素尺寸、格式和画质；应用与项目网关对该上传入口不设置文件体积或像素上限。客服需自行处理好图片后上传。公告图片继续使用原来的上传与压缩流程。

字段：`title`（选填，最多 60 字）、`subtitle`（选填，最多 160 字）、`imageUrl`（必填）、`linkUrl`（选填）、`buttonText`（最多 20 字）、`newTab`、`active`、`sortOrder`（0-99999）、`durationMs`（3000-20000）、`startsAt`、`endsAt`。时间使用 RFC3339 或 null。链接仅支持站内绝对路径与 HTTP(S)，不接受脚本、协议相对地址或带用户凭据的 URL。

已配置轮播的主标题、副标题留空时，首页和后台预览隐藏对应文案。未填写跳转地址时，隐藏轮播上的跳转按钮，包括默认创作台入口和工具入口；仍可保存按钮文字，之后填写地址再显示。自动轮播、上一张、下一张和可点击的进度指示继续可用，首页不显示播放/暂停按钮。有效地址未填写按钮文字时显示“查看详情”。没有配置轮播时，系统默认封面保留原有文案和入口。

图片可参考 1920×600、16:5（3.2:1）的版式，自行准备适合展示的清晰原图；这不是上传尺寸限制。原图不叠加明暗遮罩，全宽等比铺满横幅；受展示区域宽高影响，部分屏幕上的图片可能裁切。仅有图片而无跳转地址时不显示按钮。

用户端标题和说明叠加在图片左下角，两个入口按钮位于右下角，透明导航覆盖图片顶部。桌面端入口按钮并排；页面宽度不超过 640px 时，入口按钮上下排列。多图切换的上一张和下一张按钮分别位于图片左右两侧并垂直居中，不设边框或底色；可点击的进度指示位于底部中央并靠近底边，不设外框或背景，也不显示页码及播放/暂停按钮。窄屏为下角的文字和入口留出空间。页面宽度大于 1100px 时，横幅高度按宽度缩放，并限制在 560–600px；页面宽度为 1920px 时，横幅高度为 600px。窄屏采用自适应内容高度。

## 发布与交互

编辑弹窗按“轮播画面、标题与说明、跳转设置、发布计划”分区。右侧按 16:5 显示首页效果，也可切换“完整原图”查看全部画面，并显示原图尺寸与发布概览。播放时长以秒输入，保存时转换为接口使用的毫秒。上传异常在图片区域显示中文提示；上传中可取消，取消后旧请求不会覆盖随后编辑的轮播。保存时暂时禁用关闭操作。

部署 API、用户端和管理端。API 启动时自动执行 `00125_home_banners.sql`，不修改现有公告、订单等业务数据。当前已运行的旧 API 需要重启到新版本。

原图上传改动需同时更新管理端、Go API 和 `deploy/nginx.conf`。已有轮播图曾经被压缩的像素无法自动恢复，需要重新上传原图。若部署在额外的反向代理或 CDN 后，其上传限制由该外层服务配置决定。

首页每分钟刷新数据；支持左右切换、指示器、键盘左右键和触摸滑动。切换时随机细圆点清晰浮现、轻微散开再回拢，图片主体保持原位并柔和交接，标题、说明和入口轻淡入；不支持 WebGL 或纹理不可用时自动使用柔和淡入淡出。连续快速操作保留最后目标；减少动态效果或关闭站点动画时直接切换。

自动播放从每次切换过渡结束后开始计算当前图片的停留时长，在悬停、焦点进入和页面隐藏时暂停，减少动态效果模式默认不自动播放。首页不提供播放/暂停按钮。单张轮播隐藏切换控件，空数据或所有图片损坏时隐藏整个区域。

删除记录不会立即删除底层图片，避免影响复用同一 URL 的内容。

## 验证

服务端：`go test ./internal/httpapi -run 'HomeBanner|Announcement.*Image' -count=1`，使用独立临时数据库和模拟对象存储；验证原图上传、匿名读取的完整文件哈希，以及公告原有压缩流程。

用户端：`npx playwright test tests/e2e/home-banners.spec.js --project=chromium`。

后台：先启动独立后台开发服务，再设置 `ADMIN_BASE_URL` 执行 `tests/e2e/admin-home-banners.spec.js` 和 `tests/e2e/admin-home-banner-original-upload.spec.js`；测试覆盖原有管理流程和超过旧体积上限的原文件上传，使用模拟接口，不写业务数据库。

编辑器定向验证：`ADMIN_BASE_URL=http://127.0.0.1:3200 npx playwright test tests/e2e/admin-home-banner-editor.spec.js --project=chromium`，覆盖 1280×720、1440×900 浅深主题布局、上传错误与取消隔离、保存状态和时间转换。
