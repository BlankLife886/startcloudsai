# AI 服务与模型配置

项目使用一套统一的后台模型目录。页面不直接绑定某个域名、服务商品牌或上游模型 ID。

## 配置结构

每个服务商只保存一条连接配置：

- 自定义名称，例如 `C2A`、`RS Image`、`CRUN`。
- 调用协议：`openai` 或 `crun`。
- Base URL、单个 API Key、请求超时和启用状态。
- OpenAI 兼容服务从 `/v1/models` 读取上游模型；CRUN 从真实的 `/api/v1/models` 读取。

API Key 加密保存，后台读取时仅显示末四位掩码。当前版本不提供 Key 池、Key 轮换、权重、优先级或页面路由调度。

模型配置独立于服务商连接：

- 每个模型必须归属一个服务商，并填写该服务商实际使用的上游模型 ID。
- 类型只能是 `image` 或 `chat`。
- 可自定义用户端名称、说明、价格、折扣价、是否启用、是否对用户开放和是否默认。
- 生图模型还可标记快速模式、预计耗时和 1K/2K/4K 能力。
- 每种类型最多一个默认模型；没有显式选择时使用对应类型的默认模型。

## 统一调用

用户端只接收后台开放的模型 ID，不接收服务商 Base URL、API Key 或上游模型 ID。创建任务时，服务端根据模型 ID 解析出服务商和上游模型，并把解析结果快照写入任务参数。

`openai` 协议调用 OpenAI 兼容的模型列表、对话和图片接口。`crun` 协议仍向项目内部暴露同一套图片生成参数，由后端转换为 CRUN 的 `CreateTask`/`TaskInfo` 异步任务结构。CRUN 的差异不会传到用户端。

## 用户端模型选择

`GET /api/meta/runtime-config` 返回所有已启用、对用户开放且所属服务商已启用的模型。所有图片工作台共享生图模型目录：

- 文生图
- 插画染色
- UI 设计稿与选区素材重建
- 超高清模型图
- 游戏角色设计
- AI 助手生图与改图

`GET /api/assistant/config` 分别返回 `conversationModels` 和 `imageModels`。AI 助手的对话、分析和意图识别使用用户选择的对话模型；生图模式使用用户选择的生图模型；Agent 模式使用所选对话模型和后台默认生图模型。

用户提交的是后台模型 ID。服务端会拒绝未开放、已禁用、类型不匹配或不存在的模型，避免用户绕过后台配置提交任意上游模型名称。

## 计费

图片任务使用所选生图模型的折扣价；没有折扣价时使用标准价。模型目录尚未配置时，才兼容读取系统设置中的任务基础单价和旧服务连接，以保证迁移期间现有任务不中断。

模型目录一旦存在，用户端模型选择、实际调用服务商、上游模型和任务扣费都以模型配置为准。系统设置页不再管理服务商或模型。
