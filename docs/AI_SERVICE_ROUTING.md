# AI 服务与模型配置

项目使用一套统一的后台模型目录。页面不直接绑定某个域名、服务商品牌或上游模型 ID。

核对基线：2026-09-22 当前工作区。下文的 Worker 路由、不可变执行快照和容量规则适用于站内任务/助手；标准 `/v1/images/*` 使用 OpenAI 协议上游直通，不进入这些任务队列。协议边界见 [OPEN_API.md](OPEN_API.md)。

## 配置结构

每个服务商保存协议和一组 Base URL 路由：

- 自定义名称，例如 `C2A`、`RS Image`、`CRUN`。
- 调用协议：`openai` 或 `crun`。
- 每条路由独立配置名称、Base URL、单个 API Key、请求超时、启用状态和最大并发。
- OpenAI 兼容服务从 `/v1/models` 读取上游模型。
- CRUN 对话目录使用 `/api/v1/models`；媒体目录使用 `/api/v1/client/job/Models`。后台合并目录时保留模型类型和操作，不会把视频、音频或尚未接入的工具误标成图片模型。
- 选择 CRUN 媒体模型后，后台通过 `/api/v1/client/job/Models/{model}` 读取实时 `input_schema`，自动约束分辨率、比例、质量、输出格式、审核参数和参考图上限。

每条路由的 API Key 都独立加密保存，后台读取时仅显示末四位掩码；保存掩码不会覆盖原密钥。路由不是 Key 池，也不在同一 Base URL 内轮换 Key：一个 Base URL 对应一条明确的容量和故障边界。

模型配置独立于服务商连接：

- 每个模型必须归属一个服务商，并填写该服务商实际使用的上游模型 ID。
- 同一模型只配置一次，不需要为服务商的不同 Base URL 重复创建模型。
- 类型只能是 `image`、`chat` 或 `image_tool`。
- 可自定义用户端名称、说明、价格、折扣价、是否启用、是否对用户开放和是否默认。
- 生图模型还可标记快速模式、预计耗时和上游实时 schema 允许的图片能力。没有 `resolution` 或 `quality` 字段的模型必须使用上游内置值，不能人为勾选不存在的档位。
- 生图模型可单独开启“支持精确尺寸”，设置用户可输入的像素宽高范围与限制，使用方法见 [精确图片尺寸](EXACT_IMAGE_SIZE.md)。
- 每种类型最多一个默认模型；没有显式选择时使用对应类型的默认模型。

例如：

```text
模型 gpt-image-2
  -> 服务商 GPT Image
       -> 路由 A：Base URL A，容量 100
       -> 路由 B：Base URL B，容量 100
       -> 路由 C：Base URL C，容量 100
```

该模型的可用上游容量为 300。停用某条路由后，其容量立即从总容量中扣除，模型绑定本身不变。

## 统一调用

站内用户端只接收后台开放的模型 ID，不接收服务商 Base URL、API Key 或上游模型 ID。创建任务时解析模型、价格和允许的候选路线并写入私有 `execution_snapshots`；Worker 在已接受的候选集合内按负载率选路。后台后续编辑不能替换历史请求的模型、连接或价格，实时容量和启停规则仍控制新的准入；已有上游任务继续按原连接回收。公开 `/v1/models` 则使用自定义模型名称作为兼容协议 ID。

路由负载率使用 `running / maxConcurrency` 比较。后台 `taskFailureRetryCount` 当前默认 `2`，设为 `0` 时关闭自动重试。满足安全重试条件时，网络错误、429、可重试 5xx 或路由停用可使后续尝试优先排除失败路由；候选受创建时执行快照限制，未知受理结果不能盲目重建。异步状态轮询、失败历史和监控继续绑定对应尝试的原路由，避免查询错误的 Base URL。

后台开启“同名模型跨服务商泄压”后，Worker 会把不同服务商中同类型、同显示名称、已启用且公开的模型合并为执行候选池。跨服务商候选的有效积分必须与任务创建时冻结的单价快照完全相同，并且支持该任务实际使用的比例、质量、透明背景、输出格式、审核级别和参考图数量；任一条件不满足都不会参与调度。专用图片工具还必须具有完全相同的工具操作，例如背景移除只能切换到同为 `background_remove` 的候选。候选选择仍按各线路 `running / maxConcurrency` 比较，切换服务商只更新执行路由和上游模型，不修改任务费用。

`openai` 协议调用 OpenAI 兼容的模型列表、对话和图片接口。`crun` 对话模型调用 `/api/v1/chat/completions`；图片和图片工具由后端转换为 CRUN 的 `EstimateTask`、`CreateTask`、`TaskInfo` 异步任务结构。创建前的 `EstimateTask` 只校验上游输入和账户可承担性，不参与用户计价；`CreateTask` 永不自动重试，避免重复创建和重复扣费。

CRUN 图片请求只发送模型实时 schema 声明的字段。后台保存 `upstreamInputFields` 快照，Worker 会再次过滤任务参数，因此旧页面或异常客户端也不能向上游发送该模型不支持的 `resolution`、`quality`、`output_format`、`background` 或 `moderation`。

## 用户端模型选择

`GET /api/v1/runtime-config` 返回所有已启用、对用户开放且所属服务商已启用的模型。所有图片工作台共享生图模型目录：

- 文生图
- 插画染色
- UI 设计稿与选区素材重建
- 超高清模型图
- 游戏角色设计
- AI 助手生图与改图

专用图片工具使用独立目录。背景移除从 `features["ai.imageTools"].config.backgroundRemovalModels` 读取，只在现有图片的操作入口中出现，不进入普通生图模型选择器。用户仍只提交公开模型 ID，工具模型价格由后台单独配置。

`GET /api/v1/assistant/config` 分别返回 `conversationModels` 和 `imageModels`。AI 助手的对话、分析和意图识别使用用户选择的对话模型；生图模式使用用户选择的生图模型；Agent 模式使用所选对话模型和后台默认生图模型。

用户提交的是后台模型 ID。服务端会拒绝未开放、已禁用、类型不匹配或不存在的模型，避免用户绕过后台配置提交任意上游模型名称。

## 计费

图片任务使用所选生图模型的折扣价；没有折扣价时使用标准价。模型目录尚未配置时，才兼容读取系统设置中的任务基础单价和旧服务连接，以保证迁移期间现有任务不中断。

平台钱包以整数积分计费，订单现金以人民币分记录，虽然历史字段都使用 `Cents` 后缀，不能直接当作同一单位。充值到账积分受套餐/自定义充值比例及快照控制，不应把任意积分余额直接换算为现金。CRUN 返回的 credits、余额和预估成本供服务端判断上游是否可执行，不构成第二套面向用户的平台积分。

模型目录一旦存在，用户端模型选择、实际调用服务商、上游模型和任务扣费都以模型配置为准。系统设置页不再管理服务商或模型。

助手运行同样收费，使用 `assistantbilling` 与工作区价格；不再提供免费 `/assistant/chat` 或 `/assistant/images`。任务及助手停止前须读取服务端取消策略；上游已经受理的停止不能按普通排队取消承诺全退。标准图片直通以 `openai_image_request` 保存钱包幂等记录，并以 `developer_api` 写入成本利润账本。

旧版只有 `baseUrl`、`apiKey`、`timeoutSecs` 和 `maxConcurrency` 的服务商配置在读取时自动迁移为一条默认路由，不需要重新创建模型或手工搬迁密钥。
