## 运行方法

在仓库根目录运行，需 Node.js 22+、Go（版本按 go.mod）、Flutter 及本地 PostgreSQL。前端和移动端依赖需已安装。数据库用户需有创建临时数据库的权限。

```sh
# 显示17项对应的实际命令与工作目录
node scripts/test-task-chains.mjs --list

# 单独验证某一项；可以替换为下表任一编号
node scripts/test-task-chains.mjs --only P1-01

# 指定几项，按顺序执行
node scripts/test-task-chains.mjs --only P1-03,P1-08,P2-07

# 逐项执行全部17项
node scripts/test-task-chains.mjs
```

默认管理连接为 `postgres://localhost:5432/postgres`，可通过 `TEST_DATABASE_URL` 指定其他本机端口。该地址不是被测试业务库；每个数据库测试会创建唯一 `sc_test_*` 库，运行迁移，结束后清理。运行器拒绝远程数据库地址，不读取仓库 `.env`。

Go 测试自动启用 `-race`、`GOMAXPROCS=2`、`-p 1`，降低资源竞争。Flutter 路径可用 `FLUTTER_BIN` 指定。运行器按问题逐项执行，不会因为前一项失败而漏掉后续测试。

每次执行在 `.artifacts/task-chain-tests/<时间>/` 生成：

- `results.md`：逐项结果、实际命令、测试数量和耗时。
- `results.json`：机器可读结果。
- `<问题编号>-<步骤>.log`：完整原始输出。

退出码 0 表示所选项目全部通过。测试名未命中、没有执行测试或缺少工具，也会报告失败，不将空跑当作通过。原始普通断言脚本使用明确完成标记判断执行，不冒充 TAP 测试数量。

## 逐项测试链路与验收标准

| 编号 | 单独测试链路 | 必须满足的结果 |
|---|---|---|
| P1-01 | 创建并冻结 → attempt 到期 → HTTP 500/504/断连；再覆盖多线路乱序到期 | 最后一个可恢复 attempt 结束后任务终止并释放冻结；有新活任务时不得误终止 |
| P1-02 | 同步回退长请求仍执行 → 后台恢复扫描；再使原租约失效 | 活同步请求不被领取或判失败；确实失联后仍能接管 |
| P1-03 | CRUN 第一张已有 ID → 后续预检失败或实际 POST 结果未知 → 恢复 | 预检未提交可补缺项；POST 结果未知不重发，只接收已知 job，按实际交付结算并退差额 |
| P1-04 | 上游 pending → 本地 queued → 未确认取消/确认取消；对照尚未提交任务 | 已提交状态显示与动作一致，未确认拒绝、确认后按规则结算；真正未提交才退款 |
| P1-05 | 同会话已有 queued/running run → 编辑历史并 queue:true；对照已完成历史 | 活动任务编辑返回409，原消息/run/冻结保留；已完成历史仍可编辑 |
| P1-06 | 多图方案及逐张参考 → 并发异步提交 → 记录slot ID → 保存产物/结算 | 完整执行路径无race，逐图任务ID与交付数量一致 |
| P1-07 | 执行成功但回执丢失 → 重建缓存；另一个executor拒领；本地持久化异常 | 不重复图修改或付费任务；观察者不能删除日志；未知是否执行时明确停止自动重放 |
| P1-08 | 手持多图创建 → 中途余额不足/断连；并发重放/参数冲突/HTTP响应丢失 | 批次、子项、任务、质检、冻结整批提交或回滚；同请求返回原批次，不同参数409，越权图片拒绝 |
| P1-09 | 订阅开通 → Worker启动补发 → 周期补发 → 重复触发 | 补齐到期期次，不重复发放；沿用既有订阅周期及合同规则 |
| P2-01 | 助手上游明确failed/canceled/expired；对照临时网络错误 | 明确终态立即结束；真正重试使用新身份；含糊结果继续查询原身份 |
| P2-02 | Agent工具前/工具后遇到模型502 | 工具前可安全换路；工具执行后不从头重放整轮 |
| P2-03 | 附件读取/检索失败 → 模型尝试回答或创建文件 | 失败不算证据，不放行无依据答案/导出；成功读取流程保持可用 |
| P2-04 | Flutter读取cancelPolicy → 用户拒绝或确认停止 → API请求 | 拒绝不发请求；确认发送acknowledgeUpstream，并展示对应费用后果 |
| P2-05 | 服务端取消或客户端断网/等待超时 → 客户端状态更新/重连 | 保留服务端取消；本地监测错误不伪造failed，恢复后继续接收权威状态 |
| P2-06 | 任务创建0秒 → 重试开始70秒 → 结束100秒；批次含并行任务 | 主站/历史/电商/移动端总时间为100秒；批次按墙钟时间而非相加，单阶段耗时仍可独立统计 |
| P2-07 | 保存工作流检查点 → 修改参数/依赖/输入或中间产物 → 恢复；对照正常生成 | 不复用过期完成进度；正常输出与缓存持久化不污染版本；旧无版本进度不可静默跳过 |
| P2-08 | 工作流失败后恢复且startedAt相同 → 重试成功；随后启动其他运行 | 按独立执行身份报告正确成功/失败/取消，不被显示时间或后续任务污染 |

## 数据与发布边界

- 画布输入签名新增迁移 `00144_canvas_workflow_input_signature.sql`；部署必须使用匹配的 API 和主站版本。
- 已完成产物的指纹依据实际持久资源身份、文本及槽位。正常预览URL水合不改变版本；上传替换、重新生成和Agent图片内容编辑会使用新资源，恢复前必须重新核验。
- 缺少版本证明的旧工作流进度不能安全复用，需要显式停止旧运行后新建；修复不会自动取消用户正在执行的任务。
- CRUN 没有客户端幂等键，未知受理状态不能保证安全重发。选择交付已知结果/退款，而不是自动再提交同一未知槽位。
- 画布持久日志记录为执行中但没有结果时，会暂停自动重放，需要核对原操作结果。这是避免重复操作的故障处理，不表示该操作一定未执行。
- 总耗时保留从创建到结束的实际时间，不通过隐藏排队、失败或重试来伪造快速完成。
- 本地测试通过不等于生产已发布。上线前还应核对实际容器版本、供应商异步能力和代理超时；本轮没有真实付费生成或生产变更。
