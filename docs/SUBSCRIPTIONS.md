# 订阅周期与变更

## 周期

用户统一入口是 `/subscriptions`，旧会员入口跳转到此处。
新订阅 `billing_version=2`：生效时间为 S，购买 N 天，到期时间为 `S + N * 24小时`。
第一期在 S 立即发放，此后在 `S + k * 24小时` 发放，k 为 1 至 N-1。
不按零点刷新，不在到期时多发一期。每期额度仅在所属24小时内有效，下一期先让旧未用
额度失效，再获得新一期完整额度。Worker只补齐当前仍有效的周期，跳过已过期的遗漏期次。

历史 `billing_version=1` 保持原北京时间自然日规则和账本，不重算、不扣回、不重发。
历史积分已进入通用余额，不能可靠区分其消耗来源，因此旧订阅变更仍需人工核查。

## 积分与范围

后台套餐管理配置订阅系列、级别、网站/API 渠道、场景、模型配置 ID。
范围限制的是订阅积分用途，不是用户访问资格；通用额度仍可用于其他场景。
API Key 共用所属用户的积分，原有 Key 权限、速率、并发和日/月限额不变。

每次发放保存独立批次、权益快照和到期时间。未用积分不累计、不结转；最后一期也在
订阅结束时失效。例：每天100积分，不论上期剩100、30或0，新一期可用额度都重置为100。
扣费顺序为匹配的订阅积分、匹配的体验积分、通用积分。合同锁价时仅使用订阅积分和
符合资格的额度包，不用体验积分或普通额度包替代。部分结算也优先消耗订阅积分。预留、结算和退款在同一钱包
事务中记录分配来源。正在执行的任务保留旧期冻结额度，跨期结算不占用新一期。
失败释放时，旧期尚未过期则恢复；已过期则记入 `expired_points`，不转入新一期。
消费时校验到期时间，即使Worker延迟，也不能花掉过期积分。额度包和历史通用积分不受影响。
历史按原到期时间升级的积分保持原范围。新整期置换升级会回收旧未用积分，
新周期发放使用新权益；消费历史保留，不通过升级恢复已用订阅的自助退款资格。

## 购买与升级

用量展示区分当前整期订阅与之前整期的消费：`currentTermSpentPoints`、`priorTermSpentPoints` 按积分批次对应的订单及订阅周期归属统计，`spentPoints` 仍是整条订阅历史累计。
整期升级后展示“本次升级后使用”，不会因每天重置而清空该整期用量；原消费继续保留。无法可靠归属的历史用量返回空值，不伪装成本次使用为零。
新一期未使用但升级前有消费时，提示“升级前已使用积分，退款需人工处理”。这只是展示拆分，不重置自助退款资格。

Web 普通订阅购买会先刷新套餐配置，展示周期、每天额度、任务并发加成、价格保护、使用渠道、场景及模型限制，并说明积分重置和退款规则。
用户须勾选“我已了解订阅权益、积分重置及退款规则”后才能点击支付；关闭重开、取消后重新购买、套餐版本变化时重新确认。
Web 建单携带 `expectedPlanRevision`，服务端在套餐锁定事务中核对版本，避免确认后悄悄改用新权益。未提供该参数的旧客户端仍保持兼容。
额度包和已存在订单的继续支付不增加此勾选步骤；订单继续使用购买时权益快照。

### 合同与锁价

- 新订阅生效时生成 `billing_contract`，固定模型价格版本、额外并发名额、
  订阅锁价开关和额度包锁价开关。迁移141统一个人基础并发为4，账号各场景共享
  `平台当前基础并发 + 有效合同 concurrencyBonus`；加成为0表示不提供额外名额。
  修改套餐不追改已购合同加成，平台基础值单独生效。全局容量、供应商容量和API Key限制仍有效。
- 升级报价生成新合同，按报价时的目标方案与模型价格记录；在报价有效期内完成支付后
  切换新合同和完整新周期。取消报价不改变旧合同，重新报价采用最新价格。
- 价格簿保存模型、场景、推理档位和放大分辨率的计费规则，以内容哈希去重。
  不复制供应商密钥、提示词或上游成本。合同未记录的模型按当前公开价。
- 额度包保护是双重资格：订阅 `allowTopupPriceLock` 和实际充值批次资格必须同时允许。
  历史固定包按方案 `priceLockEligible` 判断；自定义充值还需达到建单时的单笔锁价门槛。
  资格在建单时快照，购买到账后按批次跟踪，不受后续编辑追溯影响。
- 锁价余额必须足够覆盖整次请求，且实际冻结合格批次。不足时使用公开价，已有确认金额
  不足的新任务/重试必须重新确认，不能复用退款前的低价预留。
- 退款审核、处理中及升级待支付时停用旧合同保护。此时购入额度包不恢复订阅权利。
  驳回仅恢复仍有效的旧合同；退款完成后重新购买签新合同，不恢复旧价。
- 已结算的锁价权益计入自助退款限制，即使恰逢周期交替、没有扣到订阅积分。
  额度包锁价任务未结算时也禁止自助及人工退款确认；人工例外仍保留并审计。
- 历史订阅没有可还原的价格簿时保持合同为空，不用当前价格伪造历史锁价。
  历史通用余额不自动变成合格额度包，现有账号、订单、余额不清空。

### 配置与查账

个人并发在任务与助手领取执行权时共同计数，并持有同一用户的事务锁。
UI设计生成的历史映射按服务端租约标记排除重复，不能用客户端参数绕过计数。
旧版双并发合同不改价格或期限：将原两类名额合计减去基础4，兼容为额外名额；
未记录合同权益的历史订阅不虚构加成。旧加成在升级时由新合同替换，不重复累加。

迁移140支持自定义整数元充值，最低1元。`plans.recharge_policy` 配置每元积分和
单笔锁价门槛，默认100积分/元、满30元接受锁价；方案锁价开关关闭时一律不接受。
只允许一个自定义充值方案在售，防止多个入口使用不同规则；固定额度包可同时上架，
两种入口分别控制，前台均使用套餐卡片，不相互隐藏。单笔上限为10万元，且受
10亿积分的记账上限约束。订单请求使用 `amountYuan` 和 `expectedPlanRevision`，
金额乘100转为人民币分，积分按服务器规则计算，不采信客户端传来的到账积分。
`orders.recharge_policy_snapshot` 保存旧比例和门槛，付款及补单按订单快照到账。
不同金额的待支付充值不得自动替换或并存，旧固定额度包下架后仍可核查历史订单。

套餐管理可独立配置上述开关及并发，查看套餐历史版本。任务与调度显示预留资金来源、
实际结算积分、合同与公开单价，以及每次重试的订阅/额度包批次消耗、退回、冻结和过期。
`billing_decisions` 是定价依据，`subscription_credit_allocations` 与
`topup_credit_allocations` 是实际批次账。旧批次无法恢复的结算拆分显示未分账，不用
“已分配减冻结”冒充实际消费。用户抽屉展示合同快照、本期额度、下次重置及冻结类型。
额度包账本只是通用余额的来源分类，不能再加一次成为双倍余额。

已有有效订阅或正在退订的用户只能普通购买额度包，不能再购买第二份订阅。
一个用户也只能有一笔待处理支付订单，包括待支付、待核实和已付待到账。

升级从「我的订阅」点击「升级订阅」，跳转 `/pricing?plan=subscription&upgradeFrom=订阅编号`。
价格页展示原套餐和全部标准订阅方案，当前方案标记「当前订阅」，可升级方案显示「升级至此方案」，
不符合等级、额度、使用范围、并发或价格保护要求的方案统一显示「暂不支持升级」，按钮旁的提示图标支持悬停、聚焦或点击查看原因。
选择后由服务端计算差价，在价格页内确认抵扣和新周期、选择支付方式并扫码支付；不新增补差价套餐卡片。
`/pricing?upgrade=报价编号` 保持在价格页付款；原 `/subscriptions?upgrade=...` 及变更记录继续支付入口仍兼容。
已有未完成订单时先处理原订单，退订审核及升级待支付期间不允许再次升级。最终资格和金额以服务端校验为准。

1. 服务端校验同系列、更高等级、更高额度、目标范围覆盖原权益；已绑定合同的升级
   不得降低原合同额外并发或移除原锁价资格，避免只增加积分却暗中缩减权益。
2. 新报价 `snapshot.upgradeMode=restart`。抵扣额取剩余服务时间价值、未消耗积分价值
   （仅包含有效未用额度与未来周期额度）的较小值，向下取整到分；已过期额度不再抵扣。
   应付为新套餐完整价格减抵扣额。
3. 报价有效十分钟且不超过原到期时间，保存旧有效期、两种价值、抵扣额、积分与版本快照。
   创建支付订单时锁钱包并校验消费/发放未变化，有订阅任务冻结时拒绝报价或建单。
   建单后锁定旧订阅全部未用积分（独立 `upgrade_hold`），暂停旧周期发放，通用积分不受影响。
4. 付款成功后保留同一订阅管理ID，但关闭旧发放周期、回收旧未用积分，保存置换流水；
   从实际开通时刻重新计算新套餐完整 N×24 小时，首期立即发放，其后每24小时发放。
   旧订单和旧周期不改写，旧积分回收分别记录 `upgrade_revoked_points`，不计为任务消费或退订回收。
5. 取消、过期或确认未建单会同步结束升级尝试，由事务内触发器解锁旧积分。
   解锁后过期额度失效，只补齐当前有效的一期，不补发过去期次、不延长原有效期。
   解锁后迟到的付款不能按旧报价强行置换，保留已付款事实并进入人工核查。
6. 连续整期置换使用当前套餐权益价值，不将历史付款再次累计为当前剩余服务价值。
   后续自助退款保留整个订阅的已用积分判断；未使用时退款上限受当前权益价值与实际付款约束。
   旧版升级报价/订单继续按其已保存规则处理，不回写历史交易。

示例：¥19.90/三天/每天100积分，剩完整一天且未消耗时抵扣¥6.63；
升级¥39.90/三天/每天300积分支付¥33.27，新周期完整72小时共900积分分三期发放。
若最后一期已用90积分，仅剩10积分有效，则抵扣¥0.66、支付¥39.24，过去已过期额度不抵扣。

迟到付款遇到订阅已到期或版本冲突时保留支付核查问题，交由人工处理，不能强行覆盖权益。

## 退订退款

这是一次性购买固定期限，不是自动续费。

| 状态 | 权益与资金 |
| --- | --- |
| reviewing | 提交申请即冻结该订阅积分并暂停发放，等待审核，尚未退款 |
| processing | 暂停发放并冻结该订阅未用积分，等待渠道退款 |
| completed | 渠道退款已人工确认或核定金额为零；订阅终止、未用订阅积分回收 |
| rejected | 审核未通过；解冻后只恢复有效额度与当前周期，过期额度不结转 |

新套餐的未使用全退窗口默认3小时，后台可配置0-720小时，0表示禁用该窗口。已购订阅按购买时保存的规则处理；早期未保存窗口字段的权益仍按原24小时规则处理。
使用过任何该订阅积分（包括升级前的积分）则不可退款，充值不会恢复退款资格。
用户自助入口不提供例外开关。如需人工协商，管理员在「订阅变更 → 人工例外退款」
按已完成的平台订阅订单号（含升级订单）核对用户、实付和消耗，自行填写正数退款金额、
内部处理原因并明确确认。例外金额最多为累计实付减去已退金额，不自动预填全额。
人工申请直接进入待渠道退款确认，冻结该订阅剩余积分并暂停发放；仍不能绕过进行中
任务、重复申请和金额上限。渠道成功后才能填写流水确认，未退款可驳回恢复权益。
例外标记保存在服务端订阅变更快照，操作人、内部依据和核算快照写入审计事件；
用户收到标准进度通知，不收到内部协商备注。用户无法通过传参开启例外。
窗口内未消耗订阅积分，可以按已付金额申请审核；窗口外未使用的按剩余服务时间核算上限。
申请资格检查、冻结和记录在同一钱包锁事务内完成，审批时再次校验，避免并发消费。
冻结后退款按申请时点核算，审核等待时间不会降低可退上限。
管理员可核定更低金额，不能超退；该订阅存在任务冻结积分时需先等待结算，再提交申请。

**当前支付适配器没有自动退款接口。** 审核不会自动向渠道退款。
工作人员需先在渠道完成退款，再填写真实流水号、核查说明并人工确认。
流水号不可重复，操作人、时间和说明留痕；提交申请、通过审核都不等于已退款。
这属于人工核查确认，不是平台自动验签的退款回调。核定金额为零时无需渠道退款。

退款不影响通用额度包。原订单仍保留付款事实，退款明细独立记在订阅变更中；
不能把原订单总额当作扣除退款后的净收入。发票、自动续费和跨系列直接转换不在本轮范围内。

## API

### 用户反馈与核查

用户端只展示独立的公开进度说明，不返回管理员ID或内部审计备注。审核时可另填
「用户可见说明」，内部核查说明只在后台保留。提交申请、审核通过、退款完成、
驳回恢复、升级成功、周期发放和到期均产生站内通知，按业务事件幂等去重。
通知直接链接到对应订阅；本次补发已有退订记录所缺少的当前阶段通知。

钱包把任务冻结与退订冻结分开显示。退订冻结不是AI任务消费，最终回收不重复扣减
可用余额，退订解冻也不计入任务失败退款统计。`refundHeldCents` 与 `taskFrozenCents`
分别返回两种冻结金额。

后台「订阅变更」支持按用户、申请号、平台/渠道订单号和退款流水搜索，并按状态、
类型分页筛选。「查账」联查付款订单、分页积分流水、处理时间线及核算快照。
内部备注、公开说明、操作人和金额分别记录，可导出当前页核查记录。

部分使用的示例：三天订阅实付3元，只要已消耗过订阅积分，即使还有未来未发额度也不可退款。
核算快照仍保留已使用积分、剩余时间价值等查账依据，但可退上限为零。
历史补差价升级按其实际生效区间核算。整期升级则按当前完整周期的权益价值核算，
不能将旧周期现金付款的剩余时间价值重复叠加。核算快照与历史订单保留，
已确认退款和已结束订阅不会再次产生可退额度。
只要该订阅仍有任务冻结积分，就必须先结算再申请，不影响其他通用积分任务。
