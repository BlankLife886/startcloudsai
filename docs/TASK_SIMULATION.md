# 一键任务模拟测试

入口：<http://127.0.0.1:8144/__sandbox/?view=tasks>

点击卡片上的「运行测试」或「重新运行」，程序会自动创建临时账号、提交任务、修改配置，并显示每项检查的预期值、实测值和结果。无需在浏览器中手工切换多个账号。

| 模拟项目 | 可以验证什么 |
| --- | --- |
| 多用户生图并发 | 两个账号共6张图，个人上限2、全局3，实际模拟上游最多同时处理3张，另外3张排队；图片等待时聊天仍能完成；最后验证6张交付、请求不重复、每人余额65且冻结归零。 |
| 任务中途更新模型配置 | 旧任务排队后修改模型、单价5→99、Base URL、密钥和容量；旧任务实际HTTP请求保持原配置，新任务绑定新配置；线路容量使用实时上限。 |
| 中断恢复与并发名额 | 已接收4张图后模拟中断，再降额和停用线路；验证C2A、CRUN都能保留原名额和连接，恢复不重复占用，结束后释放。 |
| 上游报错与部分退款 | 模拟500、502、断连造成第二张提交回执未知；只交付已知的一张，不再重复提交未知任务，退回未交付部分并清除冻结。 |
| 多用户对话并发 | 三个账号各4次对话，合计12次；订阅图片加成不增加对话额度。 |
| 模型调价与实际消费 | 模拟3→5积分，以及锁价订阅、新订阅、额度包和重购等情况的实际结算。 |

每次运行一组。运行中结果会自动更新，可以点击「停止测试」；停止、中断或执行不完整不会记为通过。刷新页面会保留最近结果，场景规则更新后的旧结果会提示重新验证。

图片、对话和对象存储均由本机模拟服务响应，调度、执行及结算使用项目代码。测试使用独立临时数据库，正常完成后自动清理，不消耗真实模型费用，不改动原业务库或现有手工测试账号。场景会自动控制上游等待、放行及错误；这不是可以自由配置任意用户数量或供应商参数的压测工具。

模拟通道复用原8144控制台；原来的3105前台、3200后台和8000 API仍保留。这里不会启动完整定时Worker，也不验证生产网络、真实供应商性能或全量Redis传输。

启动：

```sh
node scripts/payment-sandbox.mjs
```

代码更新后原地重启：

```sh
node scripts/payment-sandbox.mjs --restart
```

启动器会编译开启 `-race` 的场景程序。日志、进程信息与最近模拟结果保存在 `.artifacts/payment-sandbox-8144/`，其中包含本地沙盒运行凭据，不应提交到 Git。
