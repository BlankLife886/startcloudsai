# 网站维护窗口部署

适用本次用户已确认的无任务维护窗口。停止接收新任务、等待旧任务结束后使用。
不是零停机：构建阶段旧站继续服务，切换阶段关闭Gateway，网站和支付回调会暂时不可达。
支付回调恢复与主动对账使用现有机制，更新完成后检查待核实订单。

## 上传与启动

在宝塔文件管理器上传本次交付的三个文件到 `/www/wwwroot/`：

- `startcloudsai-<版本号>.tar.gz`
- `startcloudsai-<版本号>.tar.gz.sha256`
- `deploy-startcloudsai-<版本号>.sh`

不要手动覆盖当前项目，不上传本地.env、数据库或上传目录。
在宝塔终端执行交付消息中带确切版本号的这一条命令：

```bash
bash /www/wwwroot/deploy-startcloudsai-<版本号>.sh <版本号>
```

启动脚本校验SHA256、解压到独立版本目录、核对RELEASE_COMMIT，然后后台启动部署。
它立即返回PID和日志路径；这不表示部署成功。复制它输出的 `tail -n 80 -f ...` 命令查看进度。
关闭终端不会中断后台部署；查看日志时Ctrl+C只退出查看。

只有日志中出现 `DEPLOY_SUCCESS release=<版本号>` 才表示自动流程完成。
出现FAILED时保存日志，不运行旧发布脚本或手动恢复数据库。
每次尝试都有单独的备份目录，重试不会覆盖上次备份。若版本已经成功成为当前目录，不重复部署。

## 自动流程

1. 验证当前生产路径、现有容器和Compose；从当前线上目录复制生产环境配置。
2. 为旧应用镜像保留回退标签；新镜像使用本次提交号标签，逐项构建。
3. 使用部署指定Nginx镜像检测网关配置；失败时旧服务仍运行。
4. 停止Gateway、旧API、旧Worker，复查活动任务；未执行迁移前失败可重新启动旧服务。
5. 备份线上星空云绘数据库及生产环境文件；校验归档可完整读取，保存校验和与旧容器身份。
6. 启动新API自动迁移至本次最新版本；核对用户、钱包、订单、任务行数。
7. 关闭本次明确不开放的developer_api入口，其余页面配置保留。
8. 启动匹配Worker、Web、Admin；检查当前容器真实聊天和图片消费者，并检查页面可访问。
9. 切换稳定目录软链接，启动Gateway并检查健康接口、网站及后台，输出成功标记。

标准目录：`/www/wwwroot/startcloudsai`。
版本目录：`/www/wwwroot/releases/<版本号>/startcloudsai`。
备份/日志目录：`/www/backup/startcloudsai`，每次备份子目录前缀为 `maintenance-<版本号>-`。
数据库备份名：`production.dump`；原生产环境文件：`env.integrated`。

PostgreSQL、Redis、ChatGPT2API不重建或重启。既有用户图片继续使用线上OSS。
本地沙箱套餐、账号、积分、任务、服务商和模型配置不会导入线上。
默认值与用户明确批准的迁移按新版本执行：基础图片并发4加有效订阅加成，邀请功能暂停。

## 验收与失败处理

- 登录原账号；核对服务商、钱包、订阅、订单、历史图片和画布。
- 测试普通图片、参考图、助手对话及失败/取消处理；查积分结算和待核实订单。
- 开放API本次保持关闭，其偶发额度校验500是已知待修项，不作为开放验收通过。
- 本地构建和模拟测试通过不等于真实供应商及线上PG18历史数据升级已验收。
- 构建失败：旧站不变。备份阶段失败：脚本请求重新启动旧服务，请核对健康状态。
- 迁移开始后的失败：保留维护状态，停止新应用写入，检查日志、迁移版本和备份；不自动切旧账务代码。
- 产生新订单/积分消费后不能用旧备份直接覆盖数据库。回退必须保留新增业务数据并先核对版本兼容性。
- 保留旧代码、备份与镜像，禁止 `down -v`、`docker volume prune`、`docker system prune -a`。
