# 闪光卡工作台

入口 `/holo-card`，工具菜单和全部 AI 工具目录均可进入。复用 React 主站、Three.js、GSAP 和现有任务/积分/鉴权媒体接口，无新增模型依赖。

## 编辑器交互

页面采用午夜全屏展示，隐藏当前路由的全站导航，保留返回工具入口。默认直接使用“星间旅人”示例同款版式，按“选人物 → 准备主体 → 同款完成”提示下一步。用户作品和示例现在都由同一套分层渲染器与默认参数生成，背景星轨、前景光屑、独立文字、烫金与层距均已配好。右侧“皮肤 / 设计 / 玩法 / 图层 / 记录”只用于进一步调整，不是得到同款的必经步骤。面板可以 Escape 关闭并返回触发按钮，关闭期间不可交互。“纯净”模式隐藏工具，Escape 或“显示工具”可恢复。

快速开始：从样卡展厅点击“制作同款”，或在工作台点击“制作同款”（手机底部为“选图制作同款”）选择自己的图片。已有透明 PNG 经现有完整质量门检查后会直接作为主体装入模板，不调用 AI，也不修改 PNG 字节；普通照片先显示版式预览，再点击“生成同款”，确认积分、检查生成主体并点击“采用此图层”，随后四层卡片自动完成。

星轨背景、光屑、文字和空间距离不需要用户另外准备。普通照片含有原背景时，预览仍保留整图，并明确显示“待分离主体”；不能把这个状态当作已经完成人物分层。已有主体仅切到“原图对照”时，主按钮会直接返回同款效果，不重复报价或生成。最后点击“保存同款闪卡”或右上角“导出图片”保存当前画面。

空态使用完整四层样卡作为示例，明确标记且不能直接作为用户作品导出；上传后只替换同一模板中的人物图层。`TemplateCardStage` 与样卡舞台共用 `sample-relief-renderer.js`，`ASTRAL_TEMPLATE_SETTINGS` 是两者共同的默认版式。共享环境光仅使用变换与透明度动画，不创建第二个 WebGL 上下文；暂停、页面隐藏、离屏和减少动态设置会停止星尘与指针跟随。

已采用主体与待检查候选分别保存。AI 生成、读取历史或在高级图层面板导入新候选不会立即替换卡片；采用后才替换并清除旧线稿，暂不采用则保留已有作品。主“制作同款”入口中主动选择自己的透明 PNG 表示换入新图片，可通过质量门后直接使用。对象 URL 按各素材用途单独管理，丢弃候选不会撤销当前主体的预览地址；登录恢复也保留已采用主体、候选、线稿及自定义背景。

原生 2:3 人物画布保持原有对位。其他比例的透明主体（包括 image2 的方形透明画布）读取完整 Alpha 边界后，通过 UV 适配主体区域；不裁写源 PNG，Alpha=1 的细丝也纳入边界，线稿和阴影共用这一映射。普通整图按原比例放入卡面；独立背景按卡面铺满。换图或采用期间禁止导出旧帧，空的临时 Blob URL 按加载状态处理。

“重新套用示例版式”会恢复示例的背景、光泽、排版和层次，若已有主体会自动回到同款模式。自定义背景和线稿文件保留；恢复模板时线稿光效归零，新导入线稿会重新启用。用户可以在高级面板更换背景，或点击“恢复示例星轨背景”。

手机完成态收起大段步骤说明，给成品更大的展示空间；纯净模式进一步回收工具区。透明主体检查页按手机宽度排列原图、检查控件和两列确认按钮，避免套用桌面侧边距造成图片过小或按钮溢出。

模型配置、生成记录与当前任务分别刷新，错误显示在对应面板。刷新记录只读取主体任务列表，不重跑当前任务，也不清除已采用素材；记录不代表保存整张卡片的材质和排版。原图恢复失败时合格主体仍可验收，原图读取最多等待 8 秒。

导出入口明确显示“保存当前角度 · PNG”；在检查视图中也可导出当前已应用卡面，未采用的新候选不会混入导出。

动漫、像素、精灵、田园和决斗五款的第二版扩大了人物图窗，移除大面积彩色标题条和三块统计面板，保留清楚的标题、技能说明与短属性行。人物贴片在卡面的高度由旧版约 41%～59% 提升至约 54%～74%，不同皮肤仍有各自的构图。原版星间旅人保留原设计。

皮肤使用原创场景、Canvas 印刷图案与独立文字，保留用户角色；不包含官方角色或标志。选择皮肤会同步背景、卡框、文字排版、前景装饰、卡背、材质和纹理。用户已经输入的文字、主体 PNG、暂停状态、正反面与巡游开关保留。未填写的能力、描述和数值使用当前排版的默认内容。像素角色处理只改变显示颜色的采样，原图字节和连续透明边缘不改；“保留原画”可立即还原。

场景源代码是 `skin-scenes.js`，运行 `node scripts/build-card-skin-scenes.mjs` 可离线重建 `public/holo-skins/v2/` 下五张 1024×1536 PNG 母版、高质量 WebP 展示图及 360×540 预览。舞台与皮肤缩略卡共用对应场景；图库只请求约 20～32KB 的预览版，角色、卡框和文字仍独立合成。这些场景由代码绘制，不会在用户换肤时调用图像生成服务。

新增的三套风格分别由 `skin-dopamine.js`、`skin-pokemon.js`、`skin-arknights.js` 提供背景、前景、卡框、卡背与字版，通过共享绘图函数接入现有材质和分层渲染。运行 `node scripts/build-card-skin-scenes.mjs v3` 可重建 `public/holo-skins/v3/` 场景及图库预览，不重写旧版素材。场景展示图每张约 48～60KB，图库预览约 12KB。明日方舟的竖向编号在混搭时采用所选卡框的文字色；其他用户文字依然自动适配各自区域。

海洋之心由 `skin-ocean.js` 提供透明雕边、前景和字版，`skin-ocean-art.js` 提供深海场景与蓝宝石之心卡背。运行 `node scripts/build-card-skin-scenes.mjs v4` 只重建 `public/holo-skins/v4/` 的海洋素材。它与星间旅人采用相同的满版人物映射，保留原尺寸角色、独立前景和直接叠在画面上的标题；不使用照片画窗、贝母说明板或技能参数表。满版字版只显示六项可编辑元数据。借用到带画窗的卡框时，自动为标题与页眉保留安全区及深色底板；两套满版皮肤之间混搭保持满版映射。

用户提供的本轮视觉参考是原版星间旅人式满版闪卡。海洋之心以这张参考的完整度与层次为标准：角色和场景占主要画面，标题直接融入画面；纹理、边缘光与前景粒子保持层次；每套背景、雕边、字版、装饰和卡背形成一致的主题。验收使用同一人物的真实正反面大图，检查混搭、长文字和人物核心区域透明度，功能测试与主观视觉评价分别记录。

“自由混搭”允许分别选择背景、卡框、文字排版、前景装饰和卡背，也可隐藏卡框、装饰或文字。不同卡框与排版混用时，文字自动带上配套的中央字区底板，保留被选卡框的两侧设计与透明人物图窗，避免深色文字落到深色背景上。“专属配色”可改强调色。“卡面文字”提供名称、副标题、角色名称、编号、系列、版本、稀有度、属性、等级、生命值、攻击、防御、技能名称与描述；排版会缩字、换行或截省，以适应各自印刷区域。

“自备素材”支持背景、透明卡框、透明前景和卡背。卡框和前景须是真实 PNG、含透明区域与可见像素、使用 2:3 画布（如 1024×1536），并且至少 1% 像素接近完全透明（Alpha≤8）。卡框还需为当前人物图窗保留至少 50% 平均透光度，拒绝只有单个半透明像素或仅在角落透空、实际盖住人物的图片。装饰图层不使用人物的前景面积/短边门槛，因此细小粒子与低分辨率像素装饰也可导入。卡背与背景支持 PNG/JPG/WebP，按原比例铺满；透明卡背合成到对应皮肤底色。所有自备设计图层沿用 15MB / 3200 万像素上限。切换皮肤只将自备素材停用，文件仍在面板中，可点“我的素材”恢复。登录前制作草稿也包含这些素材与使用状态。

`cardSkins.js` 定义皮肤和图窗，`card-skin-art.js` 绘制独立印刷层，`cardSkinAssets.js` 使用最多八组编码素材缓存并由舞台回收对象 URL。缩略图使用小尺寸 2D Canvas，不创建额外 WebGL 渲染器。皮肤卡框位于前景和文字之间的独立空间层；混搭时人物适配卡框与文字排版图窗的交集。换肤过程中旧完整设计继续显示，新素材全部就绪后再提交，导出在装配期间禁用。原版仍使用原有图片、字版和几何卡背路径。

## 视觉玩法与状态过渡

点击右侧“视觉玩法”打开风格库，按“灵感 / 材质 / 纹理 / 动态”浏览。底部保留五种快捷材质，“更多材质”直达完整目录，选中新材质后会在快捷入口显示名称和色样。

- 9 种材质：光谱、银箔、金箔、珠光、原画、玫瑰金、冰晶、曜石、欧泊。新增材质分别调整定向缎光、分裂晶光、窄带反射和矿物变彩，实体卡缘的颜色与粗糙度一起过渡。
- 9 种纹理：流光、星砂、极光、碎钻、水波、雕纹、织光、星云、光栅。每种使用独立的空间图案；高频刻纹与细闪按屏幕导数抗锯齿，渲染跳过权重为零的纹理分支。
- 8 套灵感搭配：星河秘境、月下冰晶、蔷薇鎏金、黑曜典藏、幻彩欧泊、黄金圣印、极光回响、赛博光栅，也可点击随机按钮尝试另一套。一次只更新材质、纹理、光泽强度、轨迹和追光形状，保留图片、排版、图层深度、当前正反面及暂停状态；不会自动打开巡游。

材质与纹理通过归一化权重插值切换；连续点击会从当前显示的混合状态转向新选择。未开启巡游时，鼠标移入调节面板或材质栏会保持当前倾角，便于在同一视角比较光泽。缩略纹理用于辅助选择，实际效果以卡面为准。手机上的目录按需展开并滚动，选择区不改变画布尺寸。

- 光影巡游：环绕（12 秒）、摇曳（10 秒）、蝶舞（14 秒）和悬浮（16 秒）四条不同轨迹共用一条 GSAP 时间线。运行中改选或恢复时，从实际姿态逐渐接入。选择轨迹会开始巡游，暂停或减少动态时仅记录轨迹；悬停、拖动或方向键可接管，离开后按开关状态恢复，翻面期间暂缓巡游。
- 点亮瞬间：可选择掠光、光环、彗星或星芒，点击“点亮卡片”或双击卡面触发 0.86–1.02 秒的有限光效，结束后回到原来的光泽。中途选择其他形状在下一次触发时生效，重复触发会取消上一次；原画材质、静止及减少动态模式下不可触发。
- 透视拆层：展开实际图层间距并调整视角与画幅，合拢时恢复进入前的姿态。适用于已采用的透明主体，示例样卡也可体验。拆层期间暂缓巡游；明确启动巡游或选择运行轨迹会先合拢。切回原图模式也会合拢，避免保留无法操作的拆层状态。

首次素材就绪后渐显，换图时使用较短的过渡；加载提示由纹理真实就绪状态驱动。上传、采用与下载操作提供短暂反馈，下载提示仅表示浏览器下载已开始。视图、面板和错误提示有独立的入场过渡，关闭中的面板不接收操作。

暂停、隐藏、离屏和系统减少动态设置会停止持续运动；未完成的材质与层距过渡收敛到已选择的状态，单次扫光取消。明确点击翻面、拆层或使用方向键仍可在减少动态模式下立即更新画面。复位同时关闭巡游、合拢图层并恢复正面。

## 原图预览与人物分层

- 原图预览：普通图片先放入完整模板，可以倾斜、变换镭射材质和保存预览；整图里的背景还在，人物尚未单独分离。
- 同款人物分层：本地有效透明 PNG 可直接套入；image2 生成的主体先检查并采用，再自动组成背景、人物、光屑、文字四个真实空间图层。

分层模式默认使用示例星轨背景，也允许用户上传独立背景；不把原图叠到主体后面，不会产生重复人物。它不重建原图被人物遮挡的背景。导出的卡面 PNG 是静态视角，鼠标交互仅存在于工作台。

## RuiC 参考改进

渲染实现参考 [RuiC-card-skill](https://github.com/HRuiCcc/RuiC-card-skill/tree/24e54d38f8d629e4b344a33c674e930a6090dd98)，MIT 许可与来源保留于 `apps/web-react/public/licenses/ruic-card-skill.txt`。未安装该 skill 或 Blender，也未使用参考仓库演示中的画作。改进集中在本项目浏览器工作台：

- 卡片局部视角统一驱动色谱、窄带扫光及正负方向视差，底板、插画和卡框使用连续的卡面镭射坐标。
- 主体、星轨背景、前景光屑及程序绘制文字使用四个独立空间图层。可选线稿与主体对齐，主体比例和整卡层距可以进一步调整；默认值直接复用示例。
- 镭射使用克制的薄膜染色和扫光，不再固定向整张图片叠加彩虹亮度；提供光谱、银箔、金箔、珠光和原画。
- 支持鼠标跟随、按住拖转、真实正反面及复位；GSAP 处理缓动，暂停、隐藏和减少动态设置不持续运行。
- 线稿只接受与透明主体同尺寸的 PNG，需为稀疏黑线白底或透明底。前端检查对比度、墨色覆盖和尺寸，渲染端再次检查尺寸；换主体会清除旧线稿。尺寸一致不代表姿态自动对齐，用户仍需核对原尺寸预览。

没有照搬参考中的低 Alpha 裁切、固定像素邻域或边缘染金操作，也不使用参考素材专用的颜色提取规则。保持原来的 sRGB 颜色路径、原始 PNG 和连续半透明边缘。此版本没有自动生成背景/线稿、Blender 工程或独立网页导出，这些不属于本次渲染改进。

## image2 契约

仅选择 `ai.wallpaperGeneration.config.publicModels` 中已分配的 image2 模型，优先使用配置的默认模型，不回退至其他生图模型或 `background_remove`。选中模型需开放高质量、参考图、透明背景和合法分辨率参数。`outputFormats=[]` 表示没有可选格式、使用模型内置格式，不代表不能输出 PNG；这与普通生图和 Canvas 移除背景的接法保持一致。线路是否实际返回合格透明图仍以产物为准。

使用 `type=t2i`、一张原始参考图、`_source=holo_card`、`_kind=holo-card-subject`，明确要求 gpt-image-2 移除背景并保留主体细节，发送 `quality=high`、`inputFidelity=high`、`transparentBackground=true`、`strictAlphaOutput=true`。有 PNG 格式选项时发送 `outputFormat=png`；内置格式模式完全省略该参数，不发送空串或 `auto`。禁用自动普通抠图、提示词改写和翻译。原始上传图片不压缩；最终尺寸遵循项目原有图片尺寸规范且短边不得小于 1024。

模型与尺寸一起确定：加载时不会借用另一条模型的分辨率配置。多档模型按照原图比例检查最终像素，优先保留合法选择，否则选择可用的 2K、4K、1K；普通竖图可使用 2K，极窄画幅可能需要 4K。仅公布 1K 且支持方图的模型，在非方画幅短边不足时使用真实的 `1K / 1:1 / 1024×1024` 请求，通过提示词要求完整主体和透明留白，不以 1K 报价发送更高档尺寸。页面会明确显示这一画布调整；其他不符合精度的选项禁用。能力枚举与正常图片工作台使用相同规范化，缺失透明或高质量等能力不会自动补为支持。

先读取服务端报价，用户确认模型、档位和积分后再上传并提交。服务端报价、提交及执行线路候选均检查高保真 OpenAI 兼容适配器和完整参数；仅在模型没有可选格式时允许省略输出格式。最终图片仍必须通过真正的 PNG、尺寸和 Alpha 检查。该任务不会改派到无法透传高保真参数的 CRUN 或旧线路。请求采用稳定幂等键和服务端单价校验，网络重发不会主动换键。结果不合格不自动再次生成。恢复/刷新仅读取任务，不重新发起付费任务；任务真实停止仍使用既有取消及费用规则。

读取报价有 20 秒上限，并传递真正的取消信号；超时后解除忙碌状态，提示尚未提交任务。报价失败或超时不自动重试、上传或创建生成任务。

若某条线路返回 `Transparent background is not supported for this model.`，页面说明这条线路拒绝了本次请求的透明背景参数，原始错误可展开查看；这条错误不能推广成 gpt-image-2 无法输出透明 PNG。同一模型最新的此类失败记录会阻止原样再次提交，存在其他适合的已配置 image2 模型时可显式切换；也可以继续使用原图或导入透明 PNG。不会因刷新任务自动重试，更不会关闭 Alpha 检查来接收白底或假透明结果。

重新打开失败任务时会尝试恢复原图；只在空作品中回填，保留已有作品。成功任务的原图仍和主体候选一起保留，采用前不提前替换当前卡片。

## 透明验收边界

服务端在输出上传前，对显式启用 `strictAlphaOutput` 的任务执行真实 PNG 解码和全图 Alpha 检查：

- 短边至少 1024，最多 3200 万像素，解码前检查头部并预留内存预算。
- Alpha 不超过 8 的像素至少占 1%，外围边界至少 20% 透明。
- 至少 0.2% 像素接近不透明，或有等效的有效 Alpha 总量；允许整个主体为半透明材质。
- 保留原始 PNG 字节，不删除白色/黑色像素、不使用色键、不硬切半透明边缘。

校验失败进入现有输出处理失败、清理和退款逻辑。普通生图不受此开关影响。浏览器再次检查原始 PNG 并提供棋盘、白、黑底及 100%/200%/400% 预览。新候选确认前不会替换当前卡片，也不能作为已采用主体下载；已有作品仍可继续编辑与导出。

这些是结构性验收，能拒绝全白底、全不透明假棋盘、全透明空图等结果；不能证明语义边缘精度，也不能保证一张具有局部 Alpha 的图片内完全没有伪背景。发丝、玻璃、细线、面部一致性和背景残留必须人工核对。image2 是生成式编辑，不承诺原图主体像素级不变。
