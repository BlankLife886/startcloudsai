# 桌面端 UI 支持策略

更新时间：2026-09-22

## 产品决定

StarCloudsAI 的 Web 主站、无限画布和管理端面向桌面浏览器，本策略只约束这些 Web 界面的新增设计、开发和验收。项目另有独立 Flutter 移动客户端 `apps/mobile`，其手机/iPad 交互与发布要求见 [移动端 README](../apps/mobile/README.md)，不受本文禁止扩展手机 Web 适配的约束。

## 支持范围

- 主要设计与视觉验收视口：`1440x900`。
- 最低支持视口：`1280x720`。
- 低于 1280px 宽度的平板和手机不属于产品支持范围，不承诺布局、文字、触控或操作流程可用。
- 浏览器缩放、系统显示缩放和超宽屏仍需保证桌面主流程可读、可操作，但不为窄屏重排页面结构。

## 实现约束

- 不新增只服务于手机或平板的断点、单列重排、底部导航、移动抽屉、触控手势或移动端专属组件。
- 不为移动端隐藏、替换或简化桌面功能，也不维护两套交互流程。
- 桌面页面可以使用稳定的最小宽度；复杂表格、画布和工作台在不足宽度时允许水平滚动，不压缩成移动端卡片列表。
- 修复桌面布局时，不以“顺便兼容手机”为目标扩大改动范围。
- 仓库中的既有移动端 CSS 属于历史兼容代码：没有明确需求时不继续扩展；后续重构可以在确认不影响桌面端后逐步删除。

## 验收规则

- 页面视觉检查只覆盖 `1280x720`、`1440x900` 及必要的更大桌面视口。
- 不要求手机截图、移动端 Playwright 用例、触控目标尺寸或移动端横竖屏测试。
- `visual-mobile` 项目和部分既有触控样式仍用于历史回归；保留这些资产不等于承诺所有当前 Web 页面支持手机。
- 必须继续检查桌面端的文字溢出、组件重叠、键盘操作、焦点状态、加载/空/错误状态和 `prefers-reduced-motion`。
- 任何移动端适配工作都必须由产品负责人明确提出，不能由开发者自行推断或默认添加。
