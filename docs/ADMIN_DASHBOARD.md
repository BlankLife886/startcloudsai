# 后台首页：经营与生产总览

入口：后台「仪表盘」，路径 `/admin/`。用户画像、生命周期、价值分层与注册留存另见「用户画像大屏」(`/admin/user-profile-dashboard`)。

## 页面布局

1. **状态条**：队列是否可访问、运行告警、Go 版本、在线 Worker、队列待处理数、业务更新时间，以及刷新和说明入口。
2. **经营与任务**：八项核心指标常驻，桌面四列两行。数字、状态颜色与小屏换行区分层级，悬停指标可查看统计口径。
3. **详细指标分组**：积分总账与 AI 用量在宽屏并排，小屏纵排；质量与风险单独一行。全部保留展示，不使用分组切换。
4. **生产监控**：任务趋势、类型分布、耗时、运行资源、API 流量、系统容量、Worker 与服务商情况。

## 核心口径

| 指标 | 单位及含义 |
| --- | --- |
| 注册用户总数 / 今日新注册 | 人；累计注册规模 / 北京时间今日新增注册，不是扣除注销后的净增 |
| 今日 / 近 7 日创作差额 | 积分；创作结算积分减上游成本积分，不是人民币净利润。现金实收与退款去财务中心查看 |
| 近 24h 新建任务 | 个；滚动 24 小时内创建的任务 |
| 当前排队 / 当前执行 | 个；当前任务状态快照，区别于 Redis 队列 pending 与 Worker 数 |
| 近 24h 终态成功率 | 成功 ÷（成功 + 失败）；取消、排队和执行中任务不计入分母。无样本显示「—」 |
| 积分总账 | 积分；累计入账、累计结算和解冻退回是历史流水，当前可用与冻结是当前余额，不能把累计值简单相减作为余额 |
| 文本请求 / 图片请求 | 次；只计成功完成的请求 |
| 交付图片 | 张；按实际交付数量统计，一次请求可能交付多张图片 |
| 输入 / 输出 / 总 Token | Token；模型已记录的文本用量，不是请求次数或积分 |

「今日」按北京时间自然日；「近 7 日」「近 30 日」包含今天。「近 24h」为滚动窗口。Agent 质量统计近 7 日，计费异常统计近 30 日，其余质量与风险摘要按卡片口径读取。

## 刷新与失败状态

- 业务统计：`GET /api/v1/admin/statistics`，约每 20 秒刷新。
- 系统指标：`GET /api/v1/admin/system/metrics`，约每 5 秒刷新。
- 点击刷新同时读取两套数据。浏览器页面隐藏时暂停定时读取，返回后在下一轮定时读取恢复。离开页面清理定时器。
- 顶部「更新于」记录业务数据最近一次成功读取的时间；不代表系统采样时间或所有上游的实时状态。
- 首次读取成功前，业务指标显示「—」。数据读取成功后的 0 表示当前统计零值，无适用样本时仍显示「—」。
- 业务刷新失败保留上次成功数据，并显示错误条；系统读取失败单独显示「系统指标暂时不可用」。保留的数据可能已经过期。
- 「服务在线」只说明 Asynq / Redis 队列可访问，不代表所有模型、服务商或外部接口都正常。「运行正常」也不能替代数据读取是否成功的检查。

## 巡检建议

先看读取失败提示与更新时间，再看运行告警、排队和终态成功率。发现异常后，结合 Worker 心跳、线路容量、API 延迟和数据库连接利用率定位；不要仅凭一个绿色状态判断整个平台健康。

运行资源图是当前页面会话内采集的最近约 60 个采样点，并非持久化的历史监控。耗时图中的 P95 表示 95% 的样本耗时不超过该值；与平均值差距大时，应关注少量长尾任务。
