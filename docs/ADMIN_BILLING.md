# 后台账务与权益

## 金额口径

- 订单列表的金额汇总来自服务端，覆盖当前筛选的全部订单，不只是当前页。
- 仅平台状态为已收款待到账或已完成的订单计入确认实收；渠道应付金额不是收款证明。
- 退款仅在订阅退款确认完成后计入，审核中和处理中不扣减实收。
- 只有一笔实际付款时，可以确定该订单的退款；多笔付款没有逐单归属记录时，本单退款及净收款显示“待核对”，不随意分摊。
- 汇总按订阅去重。筛选覆盖全部关联付款时可计算整体净收款；只筛中部分付款且存在未归属退款时，不计算筛选净额。
- 净收款不是利润，尚未扣除上游成本或手续费。待核对的空值不能当作零。

## 订单管理

已过期且未收款、未发放权益的订单可以在操作列点击“删除”，需要再次确认。待支付、待核实、已收款、已完成、已取消和失败状态不开放此入口。
删除采用列表移除方式，保留原订单、操作者和时间，以及回调、对账、积分和变更审计记录。默认列表、数量及导出同步排除此类已移除记录。
删除时在事务内重新锁定订单并检查收款证据、权益关联和对账状态；有效的迟到收款证据会使订单重新显示，支付回调仍可完成到账。

支持按状态、订单类型、支付方式、关联退款、到账情况、创建日期及订单金额筛选。
搜索支持平台订单号、渠道单号、用户编号、邮箱、昵称和购买时套餐名称。
详情独立加载最新记录，展示购买时权益、充值比例、锁价资格、套餐版本、升级抵扣、当前关联订阅及处理时间线。
原订单的权益记录优先取原购买或升级前的快照，不用最新订阅权益冒充旧订单。
历史记录无法还原时明确标记未记录。处理时间线显示最近200个事件，变更列表显示最近100条并提供完整变更入口。

## 套餐变更记录

套餐卡片的“第 N 版 · 变更记录”按新到旧展示修改摘要、修改时间、修改人，以及修改前后的中文配置对比。默认只显示变动项，可切换全部配置。
记录按版本游标每次加载20条，跨页仍对比准确的上一版；不再受原先100条上限限制。
从迁移142开始，后台新增、修改、上下架、排序及推荐联动修改都在同一事务中保存修改人。没有配置变化的保存不会产生新版本。
旧记录的修改人显示“历史未记录”，没有可靠创建记录的起点显示“最早保留记录”，不反推或补造操作人。
每版显示精确关联订单数，可跳转订单管理；查询、金额统计和CSV导出使用同一套餐编号及版本筛选。
这里记录的是套餐配置变更，不代表模型实时价格表的变更，也不会改写用户已购买的权益快照。

## 人工核查

在“订阅变更 → 人工例外退款”输入原订阅或升级订单号并点击“核对订单”，可查看该订阅完整链路：付款与升级、积分批次、实际消费、升级与退款记录、支付回调及处理日志。
已完成订阅订单的详情中也提供“完整订阅链路”，日常对账无需进入退款表单。
各分类按20条分页，不再用固定100条截断历史。订单和变更编号可打开对应详情，顶部提供用户全部账务与订单入口。
订阅消费按批次分配中的实际结算记录统计，不用钱包余额变动代替；升级回收、到期、退款回收和任务释放分别列出。历史逐笔结算金额缺失时显示未记录，不当作零。
“资金硬上限”仅指累计实付减已退；“剩余权益参考值”是服务时间与未消耗权益的核算参考，均不自动填入核定金额。超过参考值会提示核对协商依据，现有人工例外权限不变。
新接口 `GET /api/v1/admin/orders/{id}/subscription-audit?section=payments&page=1` 支持 `payments/lots/usage/changes/events`。核查使用一致性事务，并回滚临时到期计算，不因查账修改余额或订单状态。
已结束订阅仍可查询链路；核算依据缺失不隐藏付款历史。链路读取失败时前端禁止提交核定。

## 用户权益与批次

用户详情新增“权益与批次”，待支付及正在处理的订阅变更置顶。
可查看实收、退款、净收款、共享并发、订阅退款资格和账户价格保护条件。
订阅历史分页展示；充值及订阅积分批次可按来源、可用、冻结、消费、过期及回收筛选。
任务冻结和退订/升级冻结分列，过期和权益回收不当成创作消费。
未归入充值批次的通用余额单独说明，不重复累计到钱包总额。
订单、用户、积分批次及订阅变更之间支持直接跳转。

## 导出与安全

订单及积分批次支持按当前已应用筛选导出CSV，包含全部符合条件的页面，单次最多5000条，超限明确报错而不静默截断。
CSV使用UTF-8 BOM，文字内容做公式注入防护。导出需要管理员会话，并同步记录操作人、筛选范围和导出数量。
金额查询与导出共用查询口径；订单读取使用一致性事务快照。快速切换筛选、订单或用户时，旧请求不会覆盖新结果。
