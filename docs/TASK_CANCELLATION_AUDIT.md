# 任务取消、费用与状态审查

日期：2026-09-09。已更新本地 API、Worker、主站和后台源码；没有发布线上，也没有调用收费模型或手工调整历史余额。

## 本次账务核对

用户截图对应的8条排队取消任务，每条均有冻结 −2、释放 +2 的钱包流水，净扣款为0，共退回16积分。原查询中另外16条成功任务合计结算32积分。

造成误解的两个已确认问题：文生图主画布的“取消生成”只处理选中的一条，未取消的同组任务会继续执行；后台“积分”列直接显示原预留 costCents，未区分取消后的实际结算。

## 修复后的规则

| 场景 | 处理 |
| --- | --- |
| 尚未发送上游请求，包括准备参考图和免费询价 | 取消后释放冻结积分，实际扣款0 |
| 已开始发送上游创建请求，或已有上游任务等待恢复 | 用户明确确认后停止接收；保留现有结算政策，不伪装成普通排队退款 |
| 文生图同组取消 | 一次事务锁定本组目标，统一取消；已完成图片保留 |
| 同组里有部分已提交图片 | 只对弹窗中明确列为已提交的任务传递收费确认；其他图片中途转入上游时，整组操作回滚并重新确认 |
| 取消请求失败或响应不确定 | 保留服务器任务追踪，不提前显示全部停止 |
| 页面关闭、切换项目或自动清理 | 不自动升级为收费停止；已有服务器任务保持可恢复 |

## 覆盖入口

- 通用任务引擎覆盖文生图、插画染色、UI设计稿、电商、模型稿、游戏素材、背景移除、媒体工具。C2A JSON/multipart、CRUN CreateTask、legacy Sub2API 和 PPT/PSD 创建请求均增加发送前检查；免费 Estimate 与参考图读取不提前进入收费停止阶段。
- AI助手生图及PPT/PSD：准备与实际发送分开，阶段和消息更新使用事务；保存取消前阶段、实际结算与退回金额。已持有上游任务的恢复记录不能按未提交队列取消。
- AI助手网页：排队移除默认不确认收费；离线补偿保存原确认位和账号，重试不升级授权；取消结果使用服务器终态信息。
- 无限画布：取消失败的节点保留追踪；工作流等待取消结果后才结束本地状态；页面卸载不再自动收费取消。已结束的助手任务等待结果同步，不冒充取消成功。
- 画布 Hosted Agent：默认先尝试未提交取消；需要收费确认时显示对话框；成功后才清空运行绑定；切换或卸载只停止本地跟踪。
- 电商：已明确确认“停止全部”时保留该授权；普通卸载/自动补偿不继承收费授权。已接受的活跃任务使用同组事务取消。
- 手持电商特殊取消接口：队列取消使用不收费授权和同组事务，不再忽略取消错误；返回实际取消项，并根据最新任务状态刷新批次状态。
- 模型稿：网络取消失败时继续追踪。设计稿主链已有二次确认，辅助素材/文件链的自动清理不再隐式收费取消。
- 插画染色：补齐运行中取消的二次确认、错误提示和忙碌状态。
- 移动端AI助手：增加 false → 409确认 → true 流程，并绑定原 run ID；普通任务详情对退款取消显示“冻结积分已退回”。
- 管理后台：区分排队取消、生成前取消、停止接收；取消不计作生成失败；显示实际结算0及已退回标记。管理员“排队取消”也检查已有上游任务。
- OpenAPI 当前没有独立取消端点；创建、报价和查询仍沿用原接口。

## 闪烁处理

临时卡片与服务器任务沿用同一 clientRequestId 作为展示身份；提交接受时不整块重建卡片。新批次选择在绘制前完成。按钮文字切换不再降低透明度，160毫秒内完成的短提交不反复显示处理中标签，忙碌禁用态不变暗。

浏览器样例实测：短请求按钮最小透明度为1，处理中标签出现0帧；同组弹窗明确显示3张可退款、1张已提交需确认的区别。实际后台页面已显示原8条记录“排队已取消 / 0 / 已退回”。
